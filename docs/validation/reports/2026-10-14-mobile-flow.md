## 本轮证据

所有浏览器测试仅打开随机命名的 `val-manager-test-*` 数据库，没有读取、清空或替换个人存档。桌面 Chrome 的设备尺寸模拟不能替代 OriginOS 桌面启动。

- 游戏全量：**253 / 253**；引擎：**154 / 154**；增加旧档跨图迁移回归、状态模型和停止控制测试。相关 39 项回归另行通过；最终补充“已确认比赛重入时结算链接可用”的回归，并通过 28 项受影响模块复核，不与全量重复累加。
- [六种视口导航点击](../2026-10-14-mobile-flow/shell-checks.json)：320×568、360×640、390×844、412×915、844×390、1280×960，验证实际 innerWidth/height、导航边界和点击命中。
- [35 页布局矩阵](../2026-10-14-mobile-flow/layout/layout-matrix.json)：普通/大字 × 6 视口，**420 项**，无页面溢出、底栏越界、过小按钮或脚本错误。最后统一战术辅助按钮后，对两张受影响页面再做 [24 项复核](../2026-10-14-mobile-flow/final-style/layout-matrix.json)。
- [真实 Worker 控制检查](../2026-10-14-mobile-flow/controls-browser.json)：真实结果回包额外延迟 1600ms；停止后只收到并提交当前一个 step；导航到设置后控件节点保持；暂停只在被规则接受时扣一次。
- 同一检查中，真实数值模型自动推进至少 20 分，逐次确认教练窗口；状态区、正文起点和动作区坐标漂移均为 **0 CSS px**。不是 vivo 帧率证据。
- [完整三条玩家旅程](../2026-10-14-mobile-flow/journeys/three-journeys.json)：首次开局；兼容旧档恢复；完整系列赛并进入下一阶段。初始三包逐张揭晓、首发与 BP、资料返回、原子检查点、战术反馈和后续阶段均走通。

## 手机最后验收

1. 用原 Chrome 桌面图标打开，确认页头为 v0.9；仍显示旧版时到设置→检查更新→保存并更新。
2. 在比赛、设置、选手资料页确认“战队 / 征战 / 档案”一直可见可点；设置首屏能读存档，末尾内容能滚动到。
3. 计算当前分时点“停止自动推进”，再去设置；返回征战应停在该分完成后的进度，不能自动多打几分。中场和战术暂停应等待确认。
4. 一张地图结束后直接查看结果，确认下一张地图名称；下一图先选特工再确认战术，系列赛结束后可进入赛程结算。
5. 测试普通/大字、竖横屏、软键盘开关和后台恢复。在桌面图标及 Chrome 浏览器两个入口分别使用“设置→导出布局诊断”。该 JSON 不包含选手卡、完整存档或比分账本；截图或诊断由用户实际设备提供后，再核对真机门槛。
