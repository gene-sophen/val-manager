# 头像连续性与清场拆包修复

本批修复用户指出的观战闪动和团灭后不拆包，正式征战默认引擎保持原样。新 Ascent v5/其余八图 v6 预览采用 `behaviorVersion: objective-2`，没有该字段的旧局继续使用原行为，不回改已提交赛果。

## 原因与改动

1. **头像跳位**：逐帧无记忆找空位，角度/空位一变就换槽。新增连续布局状态，拥挤时优先保留偏移，重新落位按回放时间平滑，额外偏移速度最多 120 图坐标/秒。死亡立即隐藏，剩余队员逐步收拢。暂停不漂移，倒退/大幅拖动时间轴重置展示布局；不改真实位置或射击。
2. **图片闪动**：普通沙盘和放大沙盘曾每帧重建全部头像/SVG。现在按队员 ID 复用头像节点，仅更新位置、颜色、生命与特效；放大图也保留底图和头像。
3. **回放假移动**：预订远处站位的 `post_pick` 曾可能被当成实际到达，即使路线没有启动。新行为明确记录预订，空间回放不把远处站位选择直接变为传送。
4. **爆能器位置被改写**：下包者仍保留携包标记，阵亡触发掉包并把目标移到死亡位置。新行为在下包完成时解除携带，固定爆能器坐标。
5. **清场后继续保枪/等集结/绕站位**：新行为根据公开清场信息重新评估可达时间，有机会的保枪者取消撤退，以真实物理路径直接跑向爆能器；不再为了战斗站位绕行。只能一人实际拆包，其他人保护。拆包必须接近且不能隔墙开始，残留封锁仍有效。
6. **拆包计时**：接近完成的那一帧不提前扣拆包时间，从开始到完成至少七秒，时间耗尽仍判引爆，不因清空攻方直接发放胜利。

路线事件在新行为中统一为坐标，避免几何缓存先收到具名站位或纯坐标时，回放记录字段不同。旧输入日志保持原形状。

## 已核实的用户观感

莲华古城预览首分清空攻方时，实际只剩约 **3.3 秒**，不足七秒；此分继续引爆是正常规则结果。播报现在明确提示「来不及完成拆包」，结束用「拆包时间耗尽，爆能器引爆」，避免仍描述已团灭的队伍在守包。
