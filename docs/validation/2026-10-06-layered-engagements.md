# Ascent 分层站位与交火样板

本批响应“区域位置与对枪点分层、适度精细、不用巨大节点图模拟枪线”的反馈，完成 Ascent v4 独立样板。不是九图战斗完工或正式引擎发布。

## 模型与实际完成

| 层 | 数量 | 职责 |
|---|---:|---|
| 宏观区域 | 17 | 保留区域 ID 和路线；负责集合、转点、补防及战术目的地 |
| 具名站位 | 52 | 真实坐标、掩体侧、保护位/探头位及微移动；普通区域 2–4 个，A/B 点稍多 |
| 交火窗口 | 12 | 描述入口、猫道、市场、二楼、回防口等接敌空间；不授予射击权限 |
| 站位射击记录 | 43 | 关联站位与窗口，列出实际可见目标站位；不是宏观路线的另一个节点图 |
| 实体分隔 | 13 | B 入口隔墙、市场两段隔墙、A 发电机/双箱、B 默认箱及中路低分隔 |

生成器 `引擎/maps/build-ascent-combat-v4.cjs` 使用保存源图的坐标变换和具体轮廓，记录障碍来源/类型。小地图细线并不全是实体墙：高墙挡视线与行走；低分隔挡行走但站立视线可越过；门缺口保持通行；二楼目前只参与射线高度。高度为游戏抽象，未声称按实测米数复刻。当前尚未审核所有细线的物理含义。

`positions` 是正式站位数据，`posts` 仅作为旧占位/移动代码的兼容入口。静态身体可见性按有向站位对预计算，使用三条身体射线；同区域不会自动互见，跨区域也不会因为路线不直接相邻而失去枪线。

仅在两人恰好位于对应站位、未移动且无动态烟/门时使用编译表。移动途中、坐标偏离、烟或门状态变化均回到实际几何；同 tick 的重复查询复用结果，坐标或动态遮挡变化立即失效。命中率消费这一暴露比例，不再额外添加固定“窗口获胜奖励”。

发电机后 → 发电机侧、市场贴墙 → 市场门架枪设置了保护/探头微路径。选手会自主检查角度，在无可见目标时回到保护位；移动有时间、不瞬移，目标站位被队友占据时保持原位。接敌/射击事件保存站位、窗口和暴露信息。玩家操作量未增加。

## 验证

- 全部引擎/游戏测试 **182 通过、0 失败**，包括旧版本、定点优化/直接射线对照、动态缓存失效、可绕行隔墙、低分隔、微移动占位、v4 恢复及浏览器 bundle 事件/帧一致性。日志：`2026-10-06-layered-engagements/full-tests.txt`。
- 新站位及全部宏观路线/两条微路径在碰撞几何中合法。
- 发电机后与入口反架同属 A 点，却无法互见；走到侧探头位后获得枪线。进点转角属于另一宏观区域，仍能看到 A 点入口。
- B 大与包点隔墙阻止直接行走/对枪；绕台阶的连续路径仍成立。
- 浏览器验证保护位/探头切换、原图叠加、层开关和 v4 回放；刷新后保持第 1 回合 0:1、54.5 秒赛果，不重新随机。
- 尝试用浏览器 viewport 能力设置 390 像素，实际页面仍报告 1280；本批不声称完成窄屏验收，响应式 CSS 待有效窄屏环境验证。

### 查询性能与对局诊断

脚本：`游戏/audit-layered-engagements.cjs`，结果：`2026-10-06-layered-engagements/audit.json`。

- 200 个定点/移动/烟遮挡状态，与直接几何查询对照 **0 不一致**。
- 每状态每 tick 六个消费者、80 次重复、两种查询校验和一致；直接身体射线 **190.5 ms**，分层查询 **113.7 ms**，该工作负载查询部分约减少 **40.3%**。重复轮次确实更新 tick，未把跨 tick 缓存当作同一时刻复用。微基准不是全引擎/赛年或帧率承诺。
- 10 个新固定种子 × 交换初始攻防，共 **20 场、429 回合**；**29,494 次射击，0 次被静态墙体阻断却仍开枪**；364 次自主角度检查。
- 攻方赢 **273/429 = 63.6%**，样本小且不是 v3 的同一组种子，不能据此推断某个机制的独立作用。仍有明显攻防偏差，不通过发布门槛。不可提高防守命中常数掩盖站位/守点/支援/技能行为问题。
