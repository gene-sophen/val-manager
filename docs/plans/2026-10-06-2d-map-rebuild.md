## 2. 地图的统一设计标准

### 2.1 真实结构，柔色表达

保留：整体方向和比例、出生点、包点、主要路线、路口宽窄、进点拐角、关键箱体、二楼/台阶、门和主要地标。简化：地面纹理、墙面装饰、小道具、树木细节和无战术意义的建筑外观。

视觉沿用当前柔色体系：浅色地面、柔和墙体、清晰边线、少量地图主题色、低密度地标。墙体和空地必须容易区分；门、可跨越低箱、不可通行高箱不能画成同一种圆角块。区域名称不代替地图形状，遮掉文字仍应能辨认地图。

每张图产出三种视图，均来自同一空间版本：BP 缩略图、比赛沙盘、开发审计图（参考叠加、通路、枪线和信息来源）。开发层不出现在普通游戏里。SVG 保持缩放清晰；不把低清海报裁切放大成战斗图。

官方参考：<https://playvalorant.com/en-us/maps/>。已有参考目录为 `素材库/地图官方/`，来源登记为 `sources.json`。官方概览图可能有图钉遮挡、缺箱体/高度信息，也可能与冻结版本不同，不能直接把图像当碰撞图；用对应版本的俯视图和实景交叉补齐。缺证据区域标记待核实，不自行发明结构。首版沿用已批准九图库，不因官网更新擅自扩充地图池。

### 2.2 一份空间基准，三个查询

新建版本化布局目录 `引擎/maps/layouts/`。建议数据契约如下，具体坐标必须测量后填写：

```js
{
  schemaVersion: 1,
  mapId: 'ascent', layoutVersion: 'ascent-v2',
  reference: { sourceId: 'frozen-reference', patch: null, hash: 'record-on-import' },
  coordinates: { width: 960, height: 960, orientation: 'reference', metersPerUnit: null },
  sites: [], spawns: [], areas: [],
  walkablePolygons: [], obstacles: [],
  levels: [], transitions: [], interactables: [],
  tacticalPositions: [], landmarks: []
}
```

`patch`、比例和坐标尚待采样；发布地图不能保留未解释的空值。地图能力分别说明：允许走过、允许看穿、允许射穿、所在层级及动态状态，不默认“能走就能看、不能走就不能看”。首版穿透只覆盖已登记材质和明确场景，不承诺完整复刻枪械穿墙。

接口：`canWalk(from, to, actor, state)`、`canObserve(observer, target, state)`、`canShoot(shooter, target, state)`、`findPath(from, to, actor, state)`。观察与射击共享可见几何；明确支持的穿透属于额外射击规则。烟雾遮视线而不堵路，关门改变通行/枪线，低箱和楼层按高度判断。导航使用区域图规划、局部几何行走，交火始终查询实际位置。

### 2.3 对枪点是候选战术站位

每个对枪点登记真实区域、坐标/层级、可架方向、用途、可撤路线及适配进点路线。掩体和暴露程度由几何计算，避免再手填一个“守点加成”抵消错误结构。

首张 Ascent 先覆盖 A/B 主入口、中路猫道/市场、包点常用掩体、二楼和回防入口。核对旧 `a_main`、`a_lobby` 的名称与真实区域映射；稳定 ID 和显示名分别管理。

四类站位均需要：进攻探点/突破位、防守架枪/交叉位、队友补枪位、转点/回防集结位。不同位置有收益和风险；强枪位可能怕闪、被夹、难撤，不存在全角度无敌站位。

选手会自动选择、移动、短暂探身和撤回。交火可以在路线上的合法位置发生，不限于抵达节点后；对枪点不能成为预先写好击杀结果的格子。新增点位先验证枪线，再交给 AI 使用。

### E8：平衡、性能和发布验收

**新增：** `游戏/audit-spatial-v2.cjs`、`游戏/tests/engine-release-v2.test.js`、`docs/validation/2026-10-06-2d-map-rebuild.md`。

1. 先用 200 场固定样本诊断；布局/行为稳定后锁参数，以至少 1,000 场等强交换攻防样本/图作为初次发布审计，并保留未参与调参的种子。区间精度不足时按精度补样本，不按好看的胜率停止。
2. 按地图、攻防、战术对、经济和英雄构成分层；每个主要战术对/经济档至少有 100 个有效回合，置信区间按整场聚类抽样，不能把同场回合当完全独立样本。
3. 做消融：新几何、对枪时序、补防、道具、战术分别开关。保留位置公平测试与强弱队梯度，定位改动原因而非只看最终平均。
4. 无真实攻防回合数据时，等强混合样本先以 45%–55% 为工程目标、超出则调查；这不是官方真实胜率，也不是给每图强制五五开。有版本匹配的侧胜率证据时设地图差异目标；总地图胜率/Ranking 不能直接充当攻防侧目标。旧 35%–65% 只够粗排错，不能作为最终质量门槛。
5. 定位防守首接触、少人守点生存/拖延、支援到达、下包和拆包的分布；强队长期更强但弱队可爆冷，合理战术有收益但不能覆盖过大实力差。
6. 记录自动单图耗时、长赛年耗时、回放大小和主线程阻塞，冻结验收设备。优先预计算静态可见性/路径、只保存事件和必要关键帧；性能不足时再评估 Worker，不先堆框架。
7. 执行全工程回归及浏览器完整赛年→次年，覆盖未晋级、补强换人、地图轮换、总决赛、旧档、刷新和窄屏。性能预算依据 E0 在固定设备的测量制定，并在进入多图前锁定。

**命令：** 新脚本实现后执行 `node 游戏/audit-spatial-v2.cjs --maps all --series 1000 --out docs/validation/2026-10-06-2d-map/release.json`；执行 `node --test 引擎/tests/*.test.js 游戏/tests/*.test.js`，沿用当前工程相应的测试加载方式。

**验收：** 每图同时通过结构、行动、回放、攻防/策略统计、版本恢复和性能审计。不能用“总共多少测试通过”代替地图真实性与玩法平衡。

## 4. 检查点与开工顺序

1. **空间样板：E0–E2。** 先交付一张可辨认、可通行、可验证枪线的 Ascent；用户可以在此修改画风，不等九图重做完。
2. **战斗样板：E3–E5。** 交付固定的守点、补防、假打、补枪、道具案例和攻防诊断，证明新的空间结构进入模拟。
3. **比赛闭环：E6。** 对接 CN/国际正式与快速比赛，确定性恢复、双方暂停和成长账本；经 N4/N5 边界回归后再接真实征战。
4. **全地图：E7。** 先用 Haven/Split 打掉双点/平面硬编码，再完成剩余地图。新地图进入轮换前必须独立通过审计。
5. **发布：E8。** 完成保留样本、长期强度和真实浏览器流程；达标后切换正式默认引擎，保留旧档版本路径。

制定计划当轮未执行上述任务。后续开工先限定 E0–E2，不同步重画九张地图、不预先调整攻防概率；玩法操作量保持当前设计。
