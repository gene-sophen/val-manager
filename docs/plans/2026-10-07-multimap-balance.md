# 其余八图行为修复与平衡计划

**Goal:** 从Haven开始逐图完善守点/补防/回防/技能/机关行为，使等实力镜像、多阵容、多排序的攻守回合比例约45–55%，保留真实坐标头像和旧回放。

**Architecture:** Ascent现有ascent-balance-3/4策略冻结。新增行为分派器与八图策略，公共动作遵循Ascent已验证的公平接触、局部技能、真实路线和半拆规则；各图入口/站位/战术/支援独立配置。开发显式指定新行为，默认入口只有经过单图检查后才切换，不改判赛果。

**Tech Stack:** CommonJS、Node node:test、现有v6地图与SVG、当前浏览器原型。

用户已授权继续，数据可随后提供；不等待数据，不额外增加玩家操作。当前混合工作区保留已有修改，不提交、不委派。

1. 新增 `引擎/behavior-policy.js`、`引擎/spatial-behavior.js`、`引擎/maps/balance-profiles.js`。引擎动作模块通过分派器调用，旧Ascent执行原策略。
2. 新增跨图/三点测试和冻结Ascent v4日志；支持 `地图ID-balance-1` 的明确版本验证、预览与恢复。保护旧objective-2日志与地图ID。
3. Haven先检查三包点分布、强接触与保留锚兵、真实补防路径；随后Split、Sunset、Breeze、Lotus、Fracture、Abyss、Summit分别检查各自入口/机关/回防。
4. 修复开发诊断中暴露的动作问题。每图开发样本与独立验证种子分开，比较首杀、下包、拆包、保枪/引爆与实际到位，不仅看平均值。不使用现实胜率直接覆盖引擎赛果。
5. 新增 `游戏/audit-map-balance.cjs`，按图记录阵容/英雄/优先级/镜像攻防与源码哈希；主样本每图至少48场成对完整地图，必要时追加分层样本。
6. 生成同源浏览器包，修复两个打包入口的依赖，更新缓存，完成回归/旧档/浏览器与物理检查。记录明确通过/未通过的地图，保持正式征战空间共核和全局发布门槛关闭。

用户提供数据的建议字段：地图、攻方/守方回合数或胜率、统计回合数、赛事范围、时间/补丁范围、链接；队伍地图胜率单独用于队伍地图特色，不与侧回合胜率混用。45–55%是本游戏等实力侧平衡目标，现实数据作合理性参照。
