# Aurora Glass 全界面重做 Implementation Plan

> 执行方式：当前对话逐项实施、检查和交付。用户已授权整个界面重做及完成后推送 GitHub；不另建正式版本目录，不操作个人数据库。

**Goal:** 以 color_design 中 Aurora Glass 的布局、卡片、标签和动效语言重做整个游戏界面，形成可辨识且适合手机执教的统一设计。

**Architecture:** 视口与滚动继续由 app-shell.css 管理；将旧 design-system.css 的有效布局规则提取为 component-layout.css，再用重写后的 design-system.css 统一视觉。新增 aurora-views.js 调整首页、战队、图鉴、备战和结算的信息构图；视图保持只读，沿用 data-action/data-go、Worker、比赛状态模型和存档事务。

**Tech Stack:** 原生 HTML/CSS/JS，现有 Noto Sans SC 字体、优化图片、SVG 图标，Node 测试与隔离 Chrome/IndexedDB 验收。

## 1. 风格与范围

- 来源：[参考仓库](https://github.com/gene-sophen/color_design)，采用 Aurora Glass，不与 CodePulse 彩色阴影混用。
- 背景 #F8FBFF，淡天空蓝/青色极光，深墨文字，蓝色主操作；轻中性阴影，圆角 14/20px，淡彩状态标签。正文与比赛数据不使用渐变文字。
- 手机固定头部、主操作、三项导航；桌面采用宽屏主区与辅助区。静态背景有氛围，正文有留白，但不牺牲 44px 触控目标或信息可见性。
- 玻璃用于低频首页/资料面板；比赛、沙盘、表单维持清晰实色。不添加持续背景运动，不在逐分刷新时重播入场动画。反馈使用 120/200ms，尊重系统及游戏减少动画设置。
- 选手卡的品质、数值与原海报保留；所有新显示的数据来自当前状态，无装饰性假成绩、假胜率或假成长。

## 2. 页面实现

1. 征战：重做首次开局封面；进行中显示队伍身份、当前任务、实际比分、赛年进度、地图与队伍状态，减少嵌套卡片。
2. 战队：清晰首发与真实三维，统一名片和地图资料；桌面首发卡排布，手机紧凑名单。
3. 卡包/组队：三包比较、五列缩略图、揭晓和品质动效、已选五人使用统一分区与状态，不改变逐张开包。
4. BP/特工/战术：海报选图、顺位、公开对手标签、职责搭配及排序一体化；选中与不可选原因可辨识。
5. 比赛/结算：突出双方比分、地图与系列进度，沙盘和战报组织一致；停止、暂停与下一分保持原语义；赛果先给结果与下一步，统计折叠。
6. 档案/图鉴/资料/荣誉/设置：统一编辑式标题、数据砖、搜索、页签、记录行与资料排版；存档卡继续置顶，危险操作独立。

## 3. 文件与执行顺序

- 新增 component-layout.css、aurora-views.js；重写 design-system.css，调整 app-shell.css 的视觉与层级，保留其唯一尺寸职责。
- index.html 与 sw.js 加载并缓存新资源；app.js 标识当前页面，使用内联 SVG 设置图标；版本统一为 v0.10。
- 游戏/tests/helpers/live-ui.cjs 加载新视图；添加只读视图、真实数据与推进入口测试。
- 更新版本契约测试、README 和验收报告；原计划及 v0.9 证据保留。

## 4. 验收

1. 只读渲染与既有流程回归；禁止靠样式隐藏必要控件来通过布局检查。
2. 35 页 × 普通/大字 × 320×568、360×640、390×844、412×915、844×390、1280×960；截图人工检查核心手机和桌面页。
3. 完整三条玩家旅程、停止与真实 Worker 回包、地图结束及 BO5 结算、存档异常回归按受影响范围检查。
4. 核对可见文本和主要按钮对比度、焦点与已选状态，非关键模块降低视觉权重。
5. 独立目录构建、GitHub 部署与线上资源一致性。iQOO Neo10 / OriginOS 6 实机验收仍需实际设备结果，不能由桌面模拟代替。
