# 战力预建模与后台赛程：实施决策

对应[开发清单](2026-10-18-ui-scroll-simulation-backlog.md)。v0.11 沿用原生界面、IndexedDB、现有赛事和空间引擎，不迁移框架。

## ADR-01：缓存能力，不预定整年赛果

`游戏/team-power.js` 输出 `team-power-1` 档案，保存五人原始分布、逐地图攻守画像、来源、置信等级及 `contentVersion / rosterRevision / teamRevision / mapRevision / fingerprint`。

缓存最多256项，以规范化完整输入作键，不用短指纹判断缓存命中。换人、能力、羁绊、熟练、教练战术、地图或内容版本变化会失效；搜索、滚动、队伍当前状态和临时战术变化不重建稳定能力。当前状态、执行排序和阶段反馈在合法比赛边界单独冻结。缓存可以丢弃，赛果不依赖缓存存续。

代价：仍需构造输入键；桌面测得命中成本约为重建的一半，未宣称手机同等收益。五人分布完整保留，首版不额外叠加未经校准的“核心选手”奖励。

## ADR-02：保留原权重，校准数值模型的确定性

基础能力继续为 `0.42 AIM + 0.30 SYN + 0.28 SEN` 的五人均值。个人SYN代表个人协同，羁绊与体系熟练分别贡献很小的队伍修正，未把三个0–100原值直接相加。

| 项目 | 数值模型作用 |
|---|---|
| 羁绊、熟练 | 相对40、50的偏移，系数0.025、0.020 |
| 教练战术 | 相对50的偏移，系数0.025 |
| 状态、地图分 | 双方差值，系数均为0.030 |
| 临场 | 影响战术克制兑现的系数，设上下限 |
| 声望 | 通过现有结算、熟识和羁绊间接生效，不另加命中率 |
| 战术 | 五类排序抽取、执行熟练、攻防克制与观察后调整 |
| 地图攻守基线 | 仅核验过列含义的数据可用，否则中性；不硬加到空间引擎 |
| 比赛波动 | 新模型在系列赛开始独立抽取小幅发挥偏移，回合另有随机流 |

回合概率为能力差的logistic变换。旧赛年保持尺度12，新赛年 `team-power-1` 使用24。首轮空间对照显示数值模型对小幅能力提升过于敏感，因此降低新模型的确定性；三维权重不变。回合概率不是赢图概率，更不是系列赛胜率。

空间引擎继续使用个体决策、技能、卡牌特性和真实交火条件。数值引擎是摘要精度，保留同一字段含义，不伪造击杀、技能或特性触发事件，也不承诺与空间模型每场同比分。条件特性的精确触发仍由空间引擎负责。跨引擎统计是初筛；96张详细地图不足以完成所有地图、特工和卡牌特性的精细标定。

## ADR-03：按原赛程顺序，在私有Worker中计算

`season-worker.js` 只加载规则和模型模块，没有DOM、存档权限。主线程冻结当前赛程输入，后台按原签表顺序执行，到玩家节点停下，整体回包后再提交。界面可以浏览、滑动、停止任务；停止会丢弃尚未提交的私有结果。失败或刷新后保留任务入口，使用同一赛年种子及已提交前缀重试。

抽签、BP、比赛、地图和发挥使用稳定ID派生的独立种子。普通NPC BP依据双方地图差异；BO5胜者组权限沿用原规则。图的胜败依赖写入节点，不能越过玩家真实结果。正式结果仍以现有 `stageSession.committed` 和阶段 `games` 为事实来源，未另造第二套赛果库。

任务号、原状态对象、阶段共同保护回包；设置等阅读页面不被完成回包跳走。浏览操作也不改变队伍成长的提交顺序。代价是同一批结果完成后才整体保存，不把中途进度冒充已持久化的赛果。

## ADR-04：冻结输入只保存一次

每场保存输入指纹和种子来源。`powerRosters` 按内容指纹归档五人；`powerInputs` 保存版本化紧凑数组，赛果仅引用输入ID。`readAudit / expandInputs` 可还原语义输入，测试核对还原后的指纹。

`powerInputFormat:1` 的数组顺序为：`[输入指纹, 主队快照, 客队快照, 地图序列, 开局攻守, BO]`。队伍快照为：`[队伍ID, 阵容引用, 队伍三维或默认, 教练三维或默认, 对应地图分, 攻防战术分, 排序或默认, 阶段修正或默认]`。不对浮点数四舍五入以换体积。默认值固定在此版本，改变必须增版本。

阶段签表的 `results` 索引只保留胜负、比分和BO；完整地图事实在 `games`，避免同一账本在索引中重复。连续两个赛年的原有2MB测试门槛保留，未放宽。存档校验拒绝未知战力/输入格式或缺失冻结阵容。原有不带战力版本的赛年保留原算法，不能因客户端升级自动改用新参数。

## UI边界

正文、资料弹窗、筛选、全屏沙盘分别拥有滚动容器。匹配结果刷新等待正在进行的触摸与惯性结束；选人、BP等直接操作立即刷新。手动推进不强制回顶。布局诊断额外记录最近16次手势的命中类型、滚动前后位置、容器尺寸和模态数量，不包含卡库或存档正文。

Aurora保留低频玻璃、浅底与蓝色操作体系；游戏状态补充语义色。采用[Refactoring UI审查准则](https://github.com/edisonmbli/refactoring-ui-skill/blob/main/skills/refactoring-ui/references/13-audit-rubric.md)检查七个视角，沿用[color_design](https://github.com/gene-sophen/color_design/tree/main/aurora-glass)的视觉方向；为游戏文字可读性和触摸稳定性，采用更深辅助文字、实底比赛组件，保留原有120/200ms反馈，不引入漂移动效。
