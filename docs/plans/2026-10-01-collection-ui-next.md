# 收藏界面制作顺序

2026-10-01。基于用户认可的白色 A 风格，当前集中处理文案精简、开包节奏与下一阶段页面制作。玩法仍在重做，本计划不预设经济、概率、阵容资格或比赛机制。

最新安排：本批收藏原型已完成，用户现要求先重做页面布局。后续按 [手机界面布局重做计划](2026-10-01-mobile-layout-rebuild.md) 执行；本文件保留前一批的验收范围。

## 本轮落实

- 产品页面删除无信息量的口号；保留页面名称、卡牌信息、进度、操作和必要空状态。设计说明放在审阅页或文档，不插入主要操作流程。
- 开包由「拆包 → 卡背 → 揭晓 → 下一张 → 卡背」改为「拆包 → 首张正面 → 连续翻阅 → 结果」。普通路径从 21 次主操作减少到 11 次；可直接查看结果。
- 封套可向右划开，也可点按钮。卡片可左滑、点击或使用下一张按钮；保留上一张和查看卡面。
- 拆封约 620ms，换卡离场 180ms、入场 280ms。钻卡增加局部光晕与一次扫光，不额外增加确认步骤；所有品质均可直接查看全部。
- 结果页采用双列紧凑卡片，展示姓名、队伍/赛事、品质与总评；点击才展开完整卡面。
- 纯展示状态，固定 10 张样例。旧概率、保底、包大小和品质排序不因此被确认为新版规则。

## 下一步：正式卡册与统一手机导航

**本批已完成（2026-10-01）**。当前入口为 `设计文档/UI原型/art-direction-03/mobile.html#album`。

- 俱乐部、选手、卡册使用统一手机外壳和底栏，开包复用同一导航。
- 卡册有 22 张四赛区样例，支持姓名/队伍搜索、品质/赛区筛选、能力/姓名排序、取消筛选、清除与空结果。
- 详情使用统一页面，含常规/赛事版本、卡面、能力与特工；从名单、卡册或开包结果进入后可回到原页面。
- 筛选、搜索及列表滚动位置在当前浏览会话中恢复；不保存选手获得、消耗、阵容等玩法数据。
- 开包结果可进入同一详情，返回时保留结果；返回卡册保持原筛选。从卡册再次进入开包会重置演示。
- 修正结果内容溢出到导航栏，以及短屏卡堆侧边接触进度条的问题。正文区、固定栏与操作区分别布局；卡片标题和标签独立排版。
- Edge 自动化通过 320/360/390/430px、640px 短屏、长姓名、内容边界、筛选取消/应用、刷新恢复、浏览器返回及完整收藏流程检查。尚未真机测试。

下表保留本批验收范围，后续进入首页与选手管理的信息布局细化；PWA 和玩法引擎仍按后文顺序进行。

下一批制作一个完整的「卡册 → 筛选/排序 → 卡面详情 → 开包 → 结果 → 返回卡册」视觉闭环。现有 `cards.html` 是设计展示板，不作为最终产品卡册。

| 顺序 | 制作内容 | 完成条件 |
| --- | --- | --- |
| 1 | 统一手机页面外壳 | 首页、选手、卡册使用同一底栏、标题栏和安全区；设计展示页不进入底栏；返回时保留列表位置 |
| 2 | 正式卡册 | 适合拇指浏览的卡片网格；姓名搜索、品质/赛区筛选、排序、清除条件、空结果；列表只展示必要信息 |
| 3 | 卡面详情与开包返回 | 卡面、赛事版本、能力与特工信息归入一致详情结构；从卡册/结果进入再返回，不丢失原筛选和位置；开包结果返回卡册示例，不声称已写入存档 |
| 4 | 手机交互检查 | 360/390/430px、短屏、安全区、浏览器返回、减动效、滑动/点击与键盘路径；原型截图和可点击入口齐备 |

此批使用已有样例数据，先完成手机单页面导航。复用共享卡面与按钮样式，逐步收拢组件，不同时重写所有旧原型。

## 后续顺序

1. 卡册闭环稳定后，细化俱乐部首页与选手管理页面的信息布局；只有明确的新玩法信息才进入页面。
2. 视觉与导航定稿后，迁入正式前端组件，补齐 PWA 安装、离线提示、资源缓存和恢复行为，进行真机检查。
3. 最后根据新版玩法规则定义数据接口与状态契约，再连接玩法引擎。

本轮不扩展商店、任务、付费货币、卡牌培养、招募概率、阵容奖励等新系统。
