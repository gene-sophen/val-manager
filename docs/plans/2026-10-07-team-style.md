# 队伍风格、地图实力与战术分 Implementation Plan

**Goal:** 备战显示对手攻防各两个风格标签，隐藏具体分数；独立地图分和十项战术分参与BP、正式/快速赛与暂停博弈。

**Architecture:** 新增纯函数team-style模块统一五类定义、软克制矩阵、风格生成/公开投影/排序/成长。新赛年生成并保存风格，旧赛年不补随机数据。数值比赛保存新输入版本；空间模型仅在明确携带风格版本时生效，冻结旧回放。地图整体侧数据用于粗模型基线和空间校准参考，不能再次叠加到空间物理结果。

**Tech Stack:** CommonJS/UMD、Node node:test、现有前端及空间共核打包。

1. 原样保存截图统计与两份本地图片。列顺序、样本单位、时间赛事待确认，未核实的数据不进入默认数值。Corrode与Summit不混为一张地图。
2. `游戏/team-style.js`：敌方攻防五分各总计250，随机分配强弱，赛年种子/队伍ID固定；玩家新阵容从50起步。所有分数0–100。只公开攻防各两标签及地图偏好。
3. 用统一5×5零和软克制矩阵替代新比赛中的索引环；暂停读取已经发生的战术/公开空间信息，综合自己的熟练分排序。玩家排序继续拥有最高操作权，不增加比例分配。
4. `round-outcome.js`：新增明确的输入版本、双方地图分、战术熟练效果、侧基线与软克制；快速赛继承已确认意图。旧进行中地图保持原算法。系列赛保留战术使用摘要供结算，不因删掉海外回合细报丢失成长。
5. `season-2026.js`：新队伍生成独立地图池与风格；提交的赛果按唯一对局/地图结算成长，预演不增长。玩家地图分仍走现有教练H/阵容M逻辑，避免双算。补强按保留人数收缩战术磨合，跨年本项回到50，原教练继承不改。
6. `spatial-match.js`、`引擎/coach.js`、`external-effects.js`：冻结风格输入，敌方按自身得分布置并在窗口调整；熟练/克制小幅影响协同和意识，卡牌三维不改，命中不被现实胜率直接覆盖。无风格的旧日志保持一致。
7. 当前原型：备战风格卡、排序页己方熟练与软克制提示、地图分驱动对手BP；敌方具体战术分不进入可见文本。刷新不变风格，正式与独立预览隔离。
8. 验证：生成稳定/预算相同/信息隐藏、矩阵一致和双视角对称、地图与战术单独改变确有影响、暂停仅用历史、结算去重、旧存档日志、浏览器包一致、完整赛年和浏览器备战/暂停。

本批不改八图balance-1的布局或行为策略；此前Split/Fracture及阵容分层平衡缺口继续保留，新风格接入后另需平衡审计。

## 本批落实

步骤2–8已实现并验证，315项全量测试通过；60完整赛年审计及浏览器备战/BP/排序/共享暂停通过。步骤1已保存原值和图片，统计口径仍待用户回复；未确认前保持中性侧基线。实现细节、默认成长参数和旧版本边界见专题设计，最终证据见[本批验收](../validation/2026-10-07-team-style.md)。
