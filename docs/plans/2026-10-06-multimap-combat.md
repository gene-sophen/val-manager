# 多地图战斗与观战 Implementation Plan

执行依据：用户已授权逐张实施，使用当前项目的版本化地图、回归测试与浏览器验收流程。

**Goal:** 清除阵亡头像占位和角标，逐张完成其余八图的独立空间、战术和回放模型。

**Architecture:** Ascent 旧 v1–v5 保持可恢复；其他地图采用新 v6 和明确地图 ID。地图宏观路线、站位、交火窗口、碰撞与机制分层，使用各自保存的源图轮廓；新地图战术/三点轮转读取配置，不复制 Ascent 区域名。

**Tech Stack:** CommonJS、版本化 JSON/SVG、Node 原生测试、浏览器同核回放。

## 1. 观战修正

- `游戏/spectator-layout.js` 只排列活人，阵亡仍记录在阵容与战报中。
- `spatial-view.js` 移除头像右上角编号，不改变真实占位或射击判定。
- 验证死亡者不推挤活人的展示位置。

## 2. 共用底座

- 新建 `引擎/maps/combat-profiles/`，每图登记区域连接、包点、进点/回防路线、掩体、高低区及机制。
- 新建编译器、地图注册表；编译真实边界路线、独立站位/交火窗口及定点可见性。
- `引擎/tactics.js` / `round.js` / `movement.js` / `abilities.js` 泛化三点、部署和转点；旧版本不改结果。
- 新 v6 接通现有三维、特性、计时射击、延迟通信、补防和暂停；地图 ID/布局版本冻结并拒绝错误恢复。

## 3. 逐图制作和检查

按 Haven → Split → Sunset → Breeze → Lotus → Fracture → Abyss → Summit 顺序：

1. 检查源图与语义区域，登记墙体、掩体和站位校正。
2. 编译单图数据与视觉碰撞覆盖，检查合法站位、宏观边和实际射线。
3. 验证两/三包点、独立进点路径、回防、地图特有空间后果。特殊动作允许简化，但不能只做动画。
4. 独立模拟并记录枪线/移动/机制问题，修正后再进入下一张。
5. 接入可选地图预览和地图检查页，浏览器查看实际回放。

## 4. 回归与交付

- 新增地图结构、三点战术、机制状态、版本恢复、每图物理射线与回放测试。
- 全工程回归和逐图固定样本诊断，记录结构检查与尚未达标的平衡/正式征战整合。
- 不以图数或测试数代替真实机制/胜率验收；常规征战切换需完成既有发布门槛。

已授权直接实施，当前目录混合改动保留，不提交或重置。
