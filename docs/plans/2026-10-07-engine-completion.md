# 比赛引擎继续完善 Implementation Plan

**Goal:** 验证外部数值和战术接口，修复未达标地图的实际行为，完善头像、技能与枪线播放，并尽量补真实内容。

**Architecture:** 已审阅的行为与特性版本保持冻结，新修复通过新行为版本分派。回放仅渲染事件日志，真实坐标和实际技能效果仍由引擎提供；视觉偏移有明确上限，不影响枪线判定。正式征战接入须以平衡、恢复和成长接口实际通过为依据。

**Tech Stack:** CommonJS/UMD、Node node:test、SVG、现有浏览器原型与隔离验收存档。

用户已授权直接继续；当前混合工作区原地推进，不重置个人数据、不委派、不提交无关改动。

1. 读取现有 Split/Fracture 分层样本并保存新诊断，区分守点首接触、补防、技能与回防。文件：`引擎/spatial-behavior.js`、`引擎/maps/balance-profiles.js`；新版本独立配置/策略，不修改 balance-1。
2. 核对 `游戏/spatial-match.js`、`引擎/external-effects.js` 和正式运行接口：三维、特性、地图分、双方优先级及暂停输入。补接口验证、输入冻结与恢复测试，声望维持间接成长用途，不额外加命中。
3. `游戏/spectator-layout.js`：头像图片24→20世界单位，接近时稳定微错位不超过3.5单位，保留实际坐标；添加轻透明。测试死亡、拖动时间轴和重复帧连续性。
4. 新增 `游戏/spectator-effects.js`：按事件时间计算短促行进枪束、烟雾/区域伤害、闪光命中、侦察/技能释放提示。`spatial-view.js` 使用同源数据，取消箭头；暂停/倒放不依赖CSS动画时钟。
5. 诊断后实施新行为版本，并用开发和独立镜像样本比较实际攻防结果；不能通过强制胜率或改判赛果修复。扩充不同战术/阵容的审计工具。
6. 可核实的内容保留来源、阵容窗口与代理标记；未经证实的原作者卡值不能编造。更新内容审计状态。
7. 重建浏览器包和缓存，运行相关及全量回归、数值接口恢复检查与实际浏览器观战，保存截图/最终报告。尚未通过的项目继续明确列出。
