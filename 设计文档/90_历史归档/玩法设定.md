## 一、平台与形态

- **最终形态**：Android / iOS 手机游戏，支持联网对战 + 单人冒险
- **现阶段开发**：先做网页端（纯 Web / H5），基本完成后做手机端适配
- 卡面与出卡特效原型已是 HTML/CSS/JS，直接作为前端技术栈基础

## 二、玩家身份与核心玩法

- 玩家身份是**教练**，组建一支自定义队伍征战 VCT
- 每次征程通过**随机抽取卡包**获取本次可用选手，再自主选五人组队（卡包设计见《抽卡系统设计.md》）
- 核心流程：随机开包 → 五人建队 → 开局专长 → 联赛备战/指挥 → 复盘与随机成长 → 阶段大成长/随机补强 → 征程结算与重新开包

## 三、单人冒险模式

- **复刻 VCT 赛事**：小组赛 → 季后赛 → 世界赛（流程简化）
- 一个赛年三个赛段，含**两个大师赛 + 一个冠军赛**，终极目标是一路征战到世界冠军
- 游戏流程 = 模拟整个赛年的过程
- 旧设想为每阶段一次模拟战斗后按强度推算晋级；**当前建议改为逐场实际赛果按公开规则决定晋级**，快速模式简化播放而非改用强度分代替比赛
- **赛季间隙**可通过抽取卡包优化队员构成，提升战斗力

## 四、成长系统（随机选择 + 阶段成长）

### 当前新增方向（2026-09-20）

- 成长是首版核心：开局教练专长、赛后随机成长选项、比赛间备战事件、阶段大成长与卡包补强。
- 具体建议采用可见三选一：随机提供机会，玩家决定强化优势、补短板或转型。条件、持续范围、适用对象、叠加/互斥规则可见。
- 选手固定能力体现个人特色，本次队伍/战术成长体现执教路线；不必引入永久卡牌等级和升星。
- 建议完整版本以一个赛年为一次征程，同一征程跨赛段保留阵容和成长，结束后重置；首版可用一个赛段测试。不是每输一场就清空。
- 建议长期保留图鉴、战绩、荣誉和横向内容解锁；本次可用选手、成长与补强资源不无限带入下一次开局。
- 允许后期构筑成型；通过固定起始额度、有限阶段补强、成长上限控制过早毕业。

以下教练三维与风格属于旧框架，需与随机成长统一对象和收益，避免重复叠加。

### 教练三维（旧框架，接入方式待修订）

教练拥有三个维度：**声望 / 战术 / 临场**。

- 三维都能影响队伍的**总体战力**
- 三维在征战过程中**逐渐改变**——既会上升也会下降
- 原设想为跨赛年存续；新方向下需要区分本次专长/训练与永久记录，跨征程数值收益及上限待定

### 执教经验与队伍风格

- 队伍经过征战积累**执教经验**与**队伍风格**，进一步提升团队战斗力
- **无论成功或失败都能积累经验**（失败也有收益，不是零和惩罚）
- **队伍风格（已拍板方向）**：如依靠个人能力的枪法风格、团队道具协同风格、战术布置执行风格等——风格**影响三维在战力转化中的比重**
