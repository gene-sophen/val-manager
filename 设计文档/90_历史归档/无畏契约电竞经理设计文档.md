## 一、游戏概述

### 1.1 定位

参考《英雄联盟电竞经理》的核心框架（选手卡牌 + 赛前战术博弈 + 自动模拟比赛），结合无畏契约（VALORANT）的玩法特性（特工 / 枪械经济 / 地图轮换 / 残局）设计的电竞经营模拟游戏。

### 1.2 核心循环

三包全览选一包 → 十人选五人 → 阶段快速赛程与一次正式 BO3 → 地图 BP、逐图选英雄与有限战术调整 → 比赛自然更新队伍和教练数值 → 两次大师赛后补强 → 赛年成绩、图鉴、选手关系与荣誉结算 → 继承已确定的长期内容，重新开包。具体规则与未决项见 2026-10-01 重做稿。

### 1.3 复杂度控制原则

- 卡面只展示三维主属性，复杂计算全部隐藏在水下
- 战斗每个判定环节只调用 1~2 个主属性，规则透明可解释
- **选手卡无养成线**（无等级 / 无特训 / 无升星），卡牌数值出厂固定；**教练有成长线**（三维：声望 / 战术 / 临场，见《玩法设定.md》）
- 深度来源更新：随机起始选手 × 英雄配队 × 地图 BP × 战术倾向与时机 × 比赛中形成的队伍变化；取消独立战术卡与赛后成长选择。
- 不含转会市场、设施经营等重度经营模块；选手数据按快照定死，动态更新后续版本再议
- 双模式：单人冒险（简化结算）+ 联网真人 BO3（完整结算），共用同一套数值底座

## 二、选手卡系统

### 2.1 卡面字段

卡面只展示以下内容，其余信息全部隐藏：

| 字段 | 说明 |
|---|---|
| 选手 ID | 真实职业选手 ID |
| 所属战队 | 按确定赛季快照写死 |
| 三维数值 | 枪法 / 协同 / 意识 |
| 品质 | 钻 / 金 / 银 / 铜 |
| 英雄池 | 按选手真实使用取 2~3 个特工，银卡及以上含 1 个招牌英雄 |
| 特性 | 金卡及以上展示（通用特性） |
| 明星时刻 | 仅钻卡展示（专属机制） |

> **选手不设固定位置**（已拍板）：存在自由人与特殊阵容，阵容合理性在英雄选择环节判定（见 2.4）。

### 2.2 三维主属性

| 属性 | 定义 | 战斗中考察的场景 |
|---|---|---|
| 枪法（AIM） | 正面火力 | 首杀对决、常规对枪、冲点质量 |
| 协同（SYN） | 团队执行 | 补枪、技能 Combo、战术执行成功率、经济纪律 |
| 意识（SEN） | 局面判断 | 残局、反绕后、转点决策、假打识破 |

**设计原则**：三维是战斗中唯一的"货币"。所有系统（暗属性、战术、枪械、教练三维、队伍风格）最终都折算成对三维的修正或对战力的修正，不存在平行数值体系。

### 2.3 品质分级（四档，已定稿）

| 品质 | 三维单维区间 | 总评区间 | 英雄池 | 招牌英雄 | 特性 | 明星时刻 |
|---|---|---|---|---|---|---|
| 铜 | 30~60 | 30~60 | 2~3 个 | 无 | 无 | 无 |
| 银 | 60~80 | 60~80 | 2~3 个 | 1 个 | 无 | 无 |
| 金 | 80~90 | 80~90 | 2~3 个 | 1 个 | 1 个通用特性 | 无 |
| 钻 | 90~96 | 90~97 | 2~3 个 | 1 个 | 1 个通用特性（卡面不显示） | **1 个专属机制** |

> 四档波段不重叠（低档上限即高档下限），档内差异拉大，个体风格更鲜明。

**递进逻辑**：每升一档恰好解锁一层玩法——

- **铜**：纯数值白板 + 英雄池，填充卡池与新手期
- **银**：招牌英雄 → 解锁数值支点
- **金**：通用特性 → 解锁机制增益
- **钻**：**明星时刻** → 解锁专属机制（见 2.7），收藏与强度双顶点

### 2.4 英雄池与招牌英雄

- 英雄池按选手真实使用取 2~3 个特工，不设入门/熟练分档
- 特工池与游戏原版保持一致，每个特工带标签用于阵容协同判定
- **英雄选择规则（已拍板）**：比赛选英雄时，由教练为每个选手指定本局使用的特工
  - 选手使用英雄池外（不擅长）的特工 → 出现失误 / 爆冷事件的概率上升
  - 选手使用**招牌英雄** → 战力提升，且打出高光表现的概率上升（具体形式与幅度待模块 4 数值设计）
  - **阵容合理性惩罚（已拍板）**：选手不设固定位置，但阵容按特工职能类型校验——**缺少某一职能类型**，或**同一职能类型 ≥3 人**时触发惩罚（惩罚形式与幅度待模块 4 数值设计）
  - 职能类型按特工归属划分（决斗 / 先锋 / 控场 / 哨卫）；**双职能特例：蝰蛇同时算控场与哨卫**（其他双职能特工在模块 2 整理标签时一并确认）

### 2.5 通用特性（金卡及以上）

通用特性是从公共词条池中分配的条件增益词条，卡面可见，同一词条会出现在不同选手身上。60 张金卡的特性方向已分配完毕（见 `选手卡/金卡特性方向.md`），具体数值待模块 4 定稿后回填。

### 2.6 明星时刻（钻卡专属机制）

明星时刻是钻卡独有的**主动型高光机制**，不止于属性增益，而是能改写单个回合走向的专属演出事件：

- 每场比赛可触发 1 次（BO3 每图 1 次），在关键局面（残局、赛点、连败止损）自动点燃
- 触发时插入专属演出动画，本回合该选手战力获得大幅加成，并附带独特规则效果
- 明星时刻与选手真实赛场名场面绑定，一人一机制；20 张钻卡的人选定稿与明星时刻命名已完成，具体机制数值后置设计

**钻卡性质与配队限制**：

- 钻卡为**切面式传奇卡**：某选手在某届关键赛事的巅峰版本，数值允许高于实际表现
- 同一选手可有多个钻卡切面，切面之间数值与技能不同
- **同一选手的钻卡与普通卡不能同时上场；每队最多上场 1 张钻卡**

### 2.7 品质锚点原则

- 钻卡：关键赛事的标志性巅峰表现（切面式）
- 金卡：世界赛队伍关键人物 / 公认核心
- 银卡：稳定首发 / 轮换
- 铜卡：新秀 / 替补 / 次级联赛上调选手
- 玩家凭赛事认知即可预判品质，学习成本为零

### 2.8 具体卡牌内容

> 见 `选手卡/` 目录：现役卡 384 张覆盖四赛区（金 60 / 银 126 / 铜 198），钻卡 20 张（每赛区 5）。结构化数据见 `数据源/cards_full.json` / `diamond_cards.json`。

## 三、暗属性系统（触发器）

### 3.1 定义

暗属性**不是固有数值**，而是「触发条件 → 主属性修正」的条件规则条目。平时完全沉睡，条件满足的瞬间生效，生效对象永远是三维主属性。

暗属性系统与品质系统**完全隔离**：低品质卡可以 roll 出优秀的触发器，高品质卡也可能拿到平庸的触发器。品质决定三维数值与英雄池下限，触发器决定个体上限与"剧本感"。

### 3.2 触发器结构

```
【触发器】= 触发条件 + 修正对象 + 修正方式 + 持续时间/次数
```

### 3.3 触发条件库（类别框架）

| 类别 | 条件示例 |
|---|---|
| 比分类 | 落后 3 分以上 / 赛点局 / 连胜中 / 连败中 |
| 回合类 | 手枪局 / 经济劣势局 / 上半场 / 下半场 / 加时 |
| 事件类 | 进入残局 1vN / 队友先阵亡 / 打出首杀后 |
| 战术类 | 执行冲点时 / 战术被克制时 / 防守被转点时 |

### 3.4 修正方式

- **加算**：直接 + 固定值
- **乘算**：按比例修正
- 持续范围：单回合 / 本图剩余回合 / 仅触发一次

> 具体词条库与 roll 值区间待模块 3 设计，本文档不再给出示例数值。

### 3.5 个体差与"识人"玩法

- 同名卡的同一触发器，roll 出不同修正幅度
- 玩家无法直接查看触发器数值，通过赛后战报评语推断
- 核心乐趣循环：抽卡 → 实战观察 → 识别极品 → 围绕其建队
- 重复卡处理：无养成体系，同名重复卡自动转为兑换货币；触发器更优的同名卡值得保留

### 3.6 与特性/明星时刻/突发事件的边界

| 系统 | 可见性 | 来源 | 定位 |
|---|---|---|---|
| 通用特性（金/钻） | 卡面可见 | 固定，公共词条池 | 标准化的条件属性增益 |
| 明星时刻（钻） | 卡面可见 | 固定，一人一机制 | 改写单回合走向的专属演出事件 |
| 暗属性触发器（全品质） | 隐藏 | 抽卡时随机 roll | 个体差来源，决定同名卡的强弱 |
| 突发事件（比赛内） | 战报可见 | 每回合随机发生 | 爆种发挥 / 爆冷失误等单回合随机事件（见 4.5） |

## 四、战斗系统框架

> 本章只定**架构与流程**，全部公式与数值待模块 4 设计产出。v3 的旧公式（战力公式、枪械系数、克制修正值等）已作废。

### 4.1 核心思路

选手三维转化为战力、暗属性转化为事件，共同构成量化**整个比赛流程**（回合内 + 整局）的数值模型——所有战术对抗、阶段推进都落到**事件成功率**的判定上。

**实现架构（已拍板）：平面地图推演引擎**

不做抽象公式结算，而是在平面地图上**真实推演每个回合**，战报是推演的记录。四层结构：

1. **地图抽象——区域节点图**：每张地图抽象为区域节点 + 通道边（约 15~20 节点/图）。节点属性：掩体质量、架枪优势方、容纳人数；边属性：通过时间、暴露度（过点是否被发现）。**仿真对象是"信息、站位、时机"，不做坐标走位与弹道物理**
2. **时间——回合时钟 tick 推进**：回合约 100 秒 + 爆能器 45 秒，逐 tick 推进移动/驻守/交火判定；防守方通过暴露通道等规则获得进攻方信息，触发转点/回防
3. **单位——10 个选手单位，轻量效用 AI**：每个决策点（岔路、遭遇、队友阵亡、下包后）从 2~4 个选项按效用选择。意识→决策质量，枪法→交火判定，协同→多人行动一致性。交火按站位优势/武器/状态逐对结算，产生击杀减员；残局是推演的自然产物
4. **战术——教练的可编排剧本（playbook）**：教练布置具体战术剧本（路线、时机、技能分配），开局/中场/暂停 = 更换或微调剧本。攻防剧本在推演中碰撞，**克制关系自然涌现**（而非查表）

**一次推演 = 三份产出**：同一份事件日志（时间戳/位置/击杀/决策）同时驱动观赛演出（雷达俯视实时播放）、文字战报、暗属性侧写证据。

**工程边界（已拍板）**：抽象天花板定在"区域+信息+时机"；技能抽象为区域修正（烟=封锁视野、闪=交火减益）；逻辑与渲染严格分离，无渲染模式下引擎必须能每秒跑数百局（平衡验证靠海量模拟统计，而非公式推胜率）。

**战力影响因素（已拍板）**：战术布置、基础战力（选手三维转化）、教练三维（声望 / 战术 / 临场）、**队内指挥（IGL）**、突发事件（爆种发挥 / 爆冷失误）、心态影响等，统一进入判定。

**IGL 指挥（已拍板）**：队伍战术能力除受教练数值影响外，还受队内 IGL 的局内影响——IGL 为全队战术协同/执行提供加成。这解释了部分选手 ACS 偏低但评分高：他们具备优秀的指挥与执行能力（数据中 `igl` 标记已存在）。

**道具使用规则（已拍板）**：道具与选手存活同为回合内动态过程；**道具释放时机由单选手 AI 自主决定**，使用灵活性受**意识**影响，多人配合场景（同步烟闪等）受**协同**影响。

**队伍风格（已拍板方向）**：如依靠个人能力的枪法风格、团队道具协同风格、战术布置执行风格等——**风格影响三维在战力转化中的比重**。

### 4.2 回合内单位模型（已拍板）

回合内是**十个选手单位**（5v5），存在**存活与死亡减员**：回合推进中选手可被击杀退出本回合，减员直接影响后续阶段判定（如残局 1vN、回防人数差）。

### 4.3 经济系统与枪械（框架已拍板）

回合按经济状态分为四种局型：

- **手枪局**
- **混起局**
- **长枪局**
- **狙击枪局**（狙击特性专属）

经济的累积/消耗规则、各局型对判定的影响，待模块 4 数值设计。

**局型分布规则（已拍板）**：正常对局以**手枪局与长枪局交替**为主；**混起局只出现在两种情况**——① 手枪局获胜后的次回合（强起扩大优势），② 对方逼近赛点且己方经济不良时的孤注一掷。

### 4.4 回合内三阶段（推演的时间结构）

三阶段是推演时间轴上的叙事分段，由引擎自然推进产生，而非独立查表结算：

1. **前期**：双方按剧本展开走位与信息试探
   - 进攻方战术族：**爆弹冲点 / 中路接触 / 边线渗透 / 假打转点**；防守方战术族：**防守前压 / 默认架点 / 赌点防守**
   - **假打转点（已拍板补充）**：制造声响与道具假象拉扯防守阵型后转点，是克制赌点/重防的关键手段，对默认架点与前压同样产生影响（前压获取的信息可能是假信息）
   - 教练的战术布置 = 编排剧本 + 调整各剧本的采用比重（开局/中场/暂停均为此操作，见 5.2）
   - 克制关系由推演自然涌现（如静音接触撞上默认架点会被逐点击破），不设人工克制表
2. **中期**：进攻方落实包点方向
   - 撞上防守重防包点 → **警察局**；错位 → 防守方**回防**
   - **防守平衡原则（已拍板）**：默认防守形态是**分站防守**；赌点是对进攻区域的预判赌博，**赌对高收益、赌错高代价**；回防是**高难度组织**——信息缺失、道具匮乏、还要防对方绕后，成功率应显著偏低
3. **后期**：根据局面进入回防、残局作战或保枪

### 4.5 突发事件与隐性状态（已拍板定位）

- 突发事件是**单个回合内随机发生**的事件（如爆种发挥、爆冷失误），不是整局级效果
- 与暗属性触发器的边界：触发器是**抽卡时固定 roll 出的个体词条**，突发事件是**每回合公共随机池**；两者都在事件成功率判定中生效

**隐性状态（暗属性层，已拍板）**：
- **熟练度**：选手使用英雄池内特工 → 熟练度高；池外特工 → 熟练度低。熟练度作为暗属性驱动**高光**与**失误**事件的触发（熟练度高易高光、低易失误）
- **心态**：对局中动态变化——**比分差距**与**连续得/失分**影响心态，心态进而影响战力（可升可降）

### 4.6 待模块 4 设计的数值内容

- 战力公式（三维 → 战力，含队伍风格对三维比重的调制、教练三维接入点）
- **推演引擎细则**：节点/边属性数值、tick 规则、信息获得规则、交火判定公式、效用 AI 的选项集与效用函数
- **战术剧本格式**：剧本的数据结构（路线/时机/技能分配）、预设模板库、采用比重的调整规则
- 经济系统数值与四局型修正
- 中期包点博弈与警察局/回防的判定细则；后期残局/保枪收益
- 突发事件池与各事件概率/效果
- 心态影响的具体形式
- 整局结算与简化结算（冒险模式）的对应算法
- **演绎节奏数值**：赛制压缩到几胜制、关键回合的判定标准、加速放映的倍率档位
- **平衡验证**：无渲染模式海量模拟（典型对阵的胜率落点、回合时长分布）

## 五、单局比赛流程（已拍板）

### 5.1 赛前阶段

1. **地图 BP**
   - 冒险模式：简化为直接一张地图
   - 联网对战：完整 BP
   - **地图属性（已拍板）**：地图有进攻图 / 防守图的倾向，影响攻防胜率；队伍有擅长与不擅长的地图，**擅长度随教练培养变化**（非固定于选手卡）
2. **英雄选择**：教练为每个选手指定特工（规则见 2.4）
3. **开局战术布置**

### 5.2 赛中阶段（教练操作）

- **中场战术布置**：1 次
- **暂停战术布置**：2 次
- **战术布置的作用（已拍板）**：编排/更换战术剧本，调整各剧本的采用比重
- **无替补、无换人**（已拍板）

**演绎节奏（已拍板）**：
- 观赛模式 = 雷达俯视推演回放（引擎事件日志驱动），**支持加速放映**
- **回合数压缩**（具体赛制/几胜制待模块 4 数值平衡时定）：整场对局时长向移动端友好靠拢
- **只完整演绎关键回合**（手枪局、经济局、赛点局、加时、明星时刻触发回合等）；普通回合快速推演直出结果
- 跳过模式：不演绎，直接出结果与战报

### 5.3 结束与加时

- **赛制压缩（已拍板方向）**：回合数较真实比赛压缩，几胜制待模块 4 数值平衡时定（v3 的 13 胜制作废）
- **加时赛（已拍板）**：暂停布置 + 一局定胜负（非多轮加时）
- 赛后战报：比分曲线、关键事件回放、选手数据；战报评语承担暗属性的"侧写透露"功能

## 六、抽卡系统（卡包制 v4，已拍板）

- **核心前提**：玩家只能使用自己开包获得的选手卡组队征战；卡包获取条件放宽
- **卡包**：按赛区区分（CN / AMER / EMEA / PAC）× 三档（初始包 / 增强包 / 登峰包）
- **品质概率（钻:金:银:铜）**：初始包 5:15:30:50 / 增强包 7.5:22.5:30:40 / 登峰包 10:30:30:30；同品质内各卡等概率
- 每包 10 张，不放回，包内不重复；跨包可重复
- **强度天花板**：每队限 1 张钻卡 + 同名钻/普通卡互斥
- 细则与论证见《抽卡系统设计.md》

## 七、系统自检

| 检查项 | 结论 |
|---|---|
| 数值主线 | 三维 → 战力 → 事件成功率 → 回合判定，单链条，易调平衡 |
| 养成线 | 选手卡无养成（数值写死）；教练三维有成长（声望/战术/临场） |
| 深度来源 | 触发器个体差 × 四档品质 × 英雄池配队 × 战术布置博弈 |
| 玩家心智负担 | 选人比三个数；深度藏在触发器、配队与战术比重 |
