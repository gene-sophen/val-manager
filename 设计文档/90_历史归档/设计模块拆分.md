## 模块 2：特工池与阵容协同 ⬜

**现状**：特工池与游戏原版保持一致、不做精简（已定）；现役 384 张卡的英雄池数据已落库（`数据源/agents.json`）；协同组合仅 3 条示例（旧数值作废，仅留思路）。

**英雄选择规则（已拍板）**：比赛时由教练为每个选手指定本局特工——
- 使用英雄池外（不擅长）的特工 → 失误/爆冷概率上升
- 使用招牌英雄 → 战力提升 + 高光概率上升（幅度待模块 4 定）
- **阵容合理性惩罚**：选手不设固定位置（允许自由人与特殊阵容）；按特工职能类型校验——缺少某一职能类型，或同一职能类型 ≥3 人时触发惩罚
- **双职能特例：蝰蛇同时算控场与哨卫**；其他双职能特工在标签整理时一并确认

**待设计内容**：
- 全部特工的标签体系设计（职能类型：决斗/先锋/控场/哨卫 + 功能标签：闪、烟、信息、位移、治疗……），需明确一个特工可带几个标签；确认双职能特工清单（已知：蝰蛇=控场+哨卫）
- 阵容协同组合完整表：组合条件（标签/数量）→ 生效场景 → 加成数值（逐项定值）
- 协同组合的互斥/叠加规则（多组合同满足时如何结算）
- 阵容合理性惩罚的具体形式（缺职能 / 同职能 ≥3 各自的修正幅度，与模块 4 对齐）

**产出物**：特工数据表 + 协同组合规则表

## 模块 4：战斗计分与结算系统 🟡

**现状**：v3 旧公式全部作废；战斗框架已重新拍板（见下）。

**双结算路线（已拍板，见《玩法设定.md》）**：
- 单人冒险：**简化结算**——每阶段一次模拟战斗定队伍强度，晋级由成绩 + 算法判定
- 联网对战：**完整结算**——真人 BO3，走完整回合结算流程
两条路线共用同一套战力公式，简化路线是完整路线的一键汇总版。

**数值模型定位（已拍板）**：选手三维转化战力 + 暗属性转化事件，共同构成量化**整个比赛流程**（回合内 + 整局）的数值模型——所有战术对抗、阶段推进都落到"事件成功率"的判定上。

**实现架构（已拍板）：平面地图推演引擎**。不做抽象公式结算，在平面地图上真实推演每个回合——
- 地图抽象为区域节点图（15~20 节点/图），仿真"信息、站位、时机"，不做弹道物理
- 回合时钟 tick 推进；10 个选手单位配轻量效用 AI（意识→决策质量、枪法→交火判定、协同→多人一致性）
- 教练战术 = 可编排剧本（playbook），克制关系由推演涌现而非查表
- 一次推演 = 三份产出：观赛演出（雷达俯视）、文字战报、暗属性侧写证据
- 工程边界：技能抽象为区域修正；逻辑与渲染分离，无渲染模式每秒数百局（平衡靠海量模拟）

**局内单回合结构（已拍板）**：

*经济系统与枪械*：回合按经济状态分为**手枪局 / 混起局 / 长枪局 / 狙击枪局**（狙击枪局为狙击特性专属）。

*战斗三阶段*：
1. **前期**：攻防双方各选战术，三种相互克制。进攻方——**爆弹冲点、中路接触、边线渗透**；防守方——**防守前压、默认架点、赌点防守**
2. **中期**：攻防双方分别选择中期侧重的包点——若选中同一包点则形成**警察局**（进攻方撞上重点多人防守的包点）；若错位则防守方需要**回防**
3. **后期**：根据局面进入回防、残局作战或保枪

**战力影响因素（已拍板）**：回合/整局的实际战力由多因素共同决定——战术布置、基础战力（选手三维转化）、教练三维（声望/战术/临场，见《玩法设定.md》）、突发事件、心态影响等，统一落到事件成功率判定上。

**单位模型（已拍板）**：回合内是 10 个选手单位（5v5），存在存活/死亡减员，减员影响后续阶段判定。

**突发事件（已拍板定位）**：单回合随机发生（爆种发挥/爆冷失误等），非整局效果；与触发器的边界——触发器是抽卡时 roll 定的个体词条，突发事件是每回合公共随机池。

**队伍风格（已拍板方向）**：个人能力枪法 / 团队道具协同 / 战术布置执行等，风格影响三维在战力转化中的比重。

**待设计内容**：
- 战力公式：三维 → 战力的转化（含队伍风格对三维比重的调制、教练三维接入点）
- 推演引擎细则：节点/边属性数值、tick 规则、信息获得规则、交火判定公式、效用 AI 选项集与效用函数
- 战术剧本（playbook）格式：数据结构、预设模板库、采用比重调整规则
- 经济系统数值：四种局型的经济累积/消耗规则、枪械档次对战力的修正
- 突发事件池：事件列表、发生概率、效果形式
- 心态影响的具体形式
- 战力影响因素的量纲统一：各因素以什么形式进入判定（乘区修正 / 事件触发 / 临时增减）
- 中期包点博弈与警察局/回防判定细则；后期残局/保枪收益
- 多修正叠加顺序与钳制规则（触发器 × 特性 × 明星时刻 × 战术修正的乘区/加区划分）
- 演绎节奏数值：赛制压缩（几胜制）、关键回合判定标准、加速放映倍率
- 完整结算伪代码（逐回合，程序可直接实现）
- 简化结算（冒险模式）= 引擎跳过渲染直接跑完（两条路线天然统一）
- 平衡性验证：无渲染海量模拟（典型对阵胜率落点、回合时长分布）
- 明星时刻在推演流程中的插入点与优先级

**产出物**：结算伪代码 + 参数定稿表 + 平衡模拟报告

## 模块 5：单局比赛流程与观赛演出 🟡

**现状**：观赛/跳过双模式与战报定位已定稿；无替补无换人（已拍板）；赛制压缩（几胜制待定，13 胜制作废）。

**单场比赛流程（已拍板）**：
1. **地图 BP**——冒险模式简化为直接一张地图；联网对战走完整 BP。地图有进攻图/防守图倾向；队伍有擅长/不擅长的地图
2. **英雄选择**——教练为每个选手指定特工（见模块 2 规则）
3. **开局战术布置**
4. **中场战术布置**
5. **两次暂停战术布置**
6. **加时赛**：暂停 + 一局定胜负（非多轮加时）

**战术布置的作用（已拍板）**：编排/更换战术剧本（playbook），调整各剧本的采用比重（开局/中场/暂停均为此操作）。

**演绎节奏（已拍板）**：观赛 = 雷达俯视推演回放（引擎事件日志驱动），支持加速放映；回合数压缩（具体赛制待定）；只完整演绎关键回合（手枪局/经济局/赛点局/加时/明星时刻回合），普通回合快速推演直出结果；跳过模式直接出战报。

**待设计内容**：
- 战术剧本编排界面的交互形式（模板选择 + 参数调整）、各节点的调整幅度差异
- 雷达俯视推演的演出规格：节点图可视化样式、击杀信息流、关键回合特写规则、加速放映的倍率与 UI
- 战报的完整数据结构（直接复用引擎事件日志：比分曲线、事件回放、选手数据）
- 跳过模式的结果呈现（直接给战报 or 简版回放）

**产出物**：流程原型说明 + 战报数据协议

## 模块 6：地图池系统 ⬜

**现状**：仅提地图池 5 张、BO1/BO3 的 ban/pick 规则；旧地图标签收益数值作废。

**已拍板方向**：地图有**进攻图/防守图**的倾向属性，影响攻防胜率；**队伍有自己擅长与不擅长的地图，擅长度随教练培养变化**（非固定于选手卡）。

**数据参考**：各地图真实赛场攻防胜率可参考号角数据站 `https://web.haojiao.cc/wiki/map/t2Ud5pOQlscKLbRC`（页面需 JS 渲染，模块 6 开工时用浏览器工具取数）。

**待设计内容**：
- 地图的选定（对齐真实赛场图池）与各自攻防倾向数值
- **每张地图的区域节点图抽象**（15~20 节点/图：节点属性=掩体/架枪优势/容纳人数，边属性=通过时间/暴露度）——推演引擎的地基数据
- 队伍擅长/不擅长地图的生成与变化规则（随教练培养）
- 地图与特工标签的联动（是否存在"某图某特工强势"的隐性搭配）
- BO3 ban/pick 的具体轮次顺序（冒险模式已简化为直接一张图）
- 图池轮换规划（随版本/赛季更新的节奏）

**产出物**：地图数据表 + ban/pick 规则细则
