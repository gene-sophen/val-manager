## 当前阶段定位

2026-10-03 用户反馈：当前资料页感觉可以；玩法可能继续重做，本目录处于准备原型阶段，部分内容暂时不完全对应玩法。

当前优先验证视觉风格、图文比例、信息密度、分区布局与查看/返回交互。玩法文档作为内容参考，不将原型中的字段、数值、流程步骤或记录结构视为玩法定案。后续页面采用可替换的展示样例；确认界面体验后，待玩法方案稳定再统一对齐并接入引擎。现有布局认可不等于对应业务规则已确认。

随后用户授权整体完成接入引擎前的内容，再集中提出局部修改。完整版本移至 `../complete-prototype-01/index.html`，40 屏总览见 `../complete-prototype-01/review.html`；本目录保留为已确认阶段的参考。

用户已确认底栏从左到右为：战队 / 征战 / 档案；征战为核心默认落点。图鉴、生涯合并到档案，名称“档案”沿用提案暂定称呼。

实现三个底栏入口与四个内容视图：征战、战队、图鉴、生涯；新增独立赛历与赛前备战子页。保留已确认的等尺寸卡片、特性与特工并排排版。

- 征战：固定常规赛对阵样例、备战入口、八阶段赛历和战队捷径。
- 赛历（`#campaign/calendar`）：突出当前阶段，过去两阶段折叠、未来阶段列表；底部进入当前对阵。
- 备战（`#campaign/prepare`）：对阵、可展开的五人阵容、当前 BP 步骤；后续特工与战术步骤弱化展示。底部可查看 BP 顺序参考，尚不能实际选图、选特工或提交战术。
- 子页独立返回与底部操作栏；从征战或赛历进入备战后分别返回来源，并恢复滚动位置。展开状态保留于当前页面运行期间。
- 战队：五人卡片、搜索、排序、详情。
- 战队资料（`#team/overview`）：羁绊 / 状态 / 熟练、按需展开的含义、五人头像及下一场；76 / 82 / 68 为固定布局样例，在原型旁明确注明。
- 选手资料（如 `#archive/player/ZmjjKK-金`）：列表点击仍先放大已确认卡面，再从“选手资料”进入独立页。人物与个人三维先展示，特工带名称，特性单独成行，共事/荣誉按需展开。同名卡版本切换不增加返回层数；底部可再次查看卡面。
- 档案 / 图鉴：22 张已解锁展示样例，姓名/队伍/特工搜索、详情；品质、赛区、排序集中在筛选面板。修改时预览结果数量，应用后更新列表；取消保留原条件，重置只改变草稿。已应用条件可单独移除。
- 档案 / 生涯：首次赛年进行中与尚无结算记录的空态。选手关系（`#archive/relationships`）、荣誉（`#archive/honors`）独立成页，当前无记录，归属说明折叠。遵循 2026-10-03 最新规则：同一选手各版本共享熟识，荣誉归属实际参赛卡版本。
- 底栏切换保留分区位置；图鉴、生涯分别记住位置。档案页内切换固定在滚动区顶部。搜索筛选存于浏览器会话，不写入玩法存档。
- `card-view.js` 从已确认的 players-balance 渲染函数提取为本目录展示组件。旧入口未改；结构稳定后再统一所有原型的共享来源。
- `trait-snapshot.js` 只引用金卡特性方向文档里的名称，未包含规则效果。
